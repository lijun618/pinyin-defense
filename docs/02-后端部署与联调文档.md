# 拼音战机 · 后端部署与联调文档

> 本文档描述「单文件游戏 + MySQL + FastAPI」的完整落地流程，从零到可运行的每一步都可以照着做。
> 目标环境：Windows 10 + MySQL 8.0 + Python 3.10+。

---

## 一、系统架构

```
┌──────────────────────────────┐         ┌───────────────────────────┐
│  拼音战机.html（浏览器）      │  HTTP   │  FastAPI (uvicorn:8000)    │
│  · 游戏主循环 Canvas          │ ──────► │  /register  /login         │
│  · 登录/注册页  · 结算页      │  JSON   │  /save_game_record         │
│  · 排行榜页                   │ ◄────── │  /get_rank  /health        │
└──────────────────────────────┘         └────────────┬──────────────┘
                                                      │ pymysql
                                                      ▼
                                         ┌───────────────────────────┐
                                         │  MySQL 8.0                 │
                                         │  pinyin_war_game           │
                                         │  ├ users                   │
                                         │  └ game_records            │
                                         └───────────────────────────┘
```

- **前端**：单个 HTML，无需构建，双击即玩，通过 `fetch` 调用后端。
- **后端**：FastAPI + pymysql，密码用 bcrypt 摘要存储，绝不落明文。
- **数据库**：MySQL 8.0，`utf8mb4` 全链路，支持中文用户名。

## 四、第一步：建库建表

在项目根目录执行（把密码替换成你自己的 root 密码）：

```bash
mysql -uroot -p < sql/init_db.sql
```

或者进入 MySQL 客户端后 `source` 该文件：

```sql
SOURCE E:/WorkBuddyProject/pinyindefense/sql/init_db.sql;
```

### 表结构说明

**users —— 用户表**

| 字段 | 类型 | 说明 |
|---|---|---|
| user_id | INT UNSIGNED PK AUTO_INCREMENT | 用户主键 |
| username | VARCHAR(32) UNIQUE | 登录名，唯一索引 `uk_username` |
| password_hash | VARCHAR(255) | bcrypt 摘要，形如 `$2b$12$...` |
| create_time | DATETIME DEFAULT CURRENT_TIMESTAMP | 注册时间 |

**game_records —— 成绩表（每人仅一条，最近得分 + 最高分及其难度）**

| 字段 | 类型 | 说明 |
|---|---|---|
| record_id | INT UNSIGNED PK AUTO_INCREMENT | 记录主键（同一用户覆盖时保持不变） |
| user_id | INT UNSIGNED UNIQUE | 外键 → `users.user_id`，`ON DELETE CASCADE`；唯一索引 `uk_user_id` 保证一人一条 |
| total_score | INT | 最近一局得分（每次都覆盖，无论高低） |
| difficulty | VARCHAR(10) | 最近一局难度：`easy` / `normal` / `hard` |
| best_score | INT | 历史最高分（`GREATEST`，只升不降） |
| best_difficulty | VARCHAR(10) | 取得历史最高分时的难度，随最高分一起刷新 |
| correct_rate | DECIMAL(5,2) | 最近一局的正确率（0–100，保留 2 位） |
| play_duration | INT | 游玩时长（秒） |
| play_time | DATETIME DEFAULT CURRENT_TIMESTAMP | 记录写入时间 |

### 验证建库结果

```sql
USE pinyin_war_game;
SHOW TABLES;
DESC users;
DESC game_records;
SHOW CREATE TABLE game_records\G    -- 确认外键 fk_records_user 与唯一索引 uk_user_id 都在
```

## 五、第二步：安装 Python 依赖

```bash
cd backend
python -m pip install -r requirements.txt
```

> **重要**：`requirements.txt` 已把 `bcrypt` 锁定为 `4.0.1`。
> bcrypt 5.x 移除了 `__about__` 属性，passlib 1.7.4 读取时会抛 `AttributeError`，
> 表现为"注册接口 500"。若已误装高版本，先卸载再装：

```bash
python -m pip uninstall -y bcrypt
python -m pip install bcrypt==4.0.1
```

依赖自检（不会连数据库，只验证哈希链路）：

```bash
python security.py
# 期望输出：
# hash: $2b$12$....
# verify ok: True
# verify bad: False
```

## 八、接口说明

统一约定：请求与响应均为 `application/json`；业务失败返回 HTTP 200 + `{"ok": false, "msg": "原因"}`，
网络/参数错误返回 4xx/5xx。

### 1. POST /register —— 注册

```json
// 请求
{ "username": "testplayer", "password": "123456" }

// 成功
{ "ok": true, "user": { "user_id": 1, "username": "testplayer" } }

// 用户名重复
{ "ok": false, "msg": "用户名已存在" }
```

校验规则：
- **用户名**：3–32 个字符，允许 **中文（汉字）、英文字母、数字、下划线**，
  首尾空格会被自动去除；不允许空格、标点、表情等。
- **密码**：6–64 位，任意字符。
- 不满足约束返回 `422`，`detail[0].msg` 为可读原因；用户名重复返回 `ok:false`。

> 长度按**字符数**计：`users.username` 为 `utf8mb4 VARCHAR(32)`，一个汉字占 1 个字符位
> （占 3 字节），与前端 `maxlength` / JS `length` / Python `len()` 口径一致，
> 因此 32 个汉字可以正常注册，第 33 个字符会被拒绝。

### 2. POST /login —— 登录

```json
// 请求
{ "username": "testplayer", "password": "123456" }

// 成功
{ "ok": true, "user": { "user_id": 1, "username": "testplayer" } }

// 失败（用户名不存在与密码错误返回同一提示，避免枚举用户）
{ "ok": false, "msg": "用户名或密码错误" }
```

### 3. POST /save_game_record —— 保存对局

```json
// 请求
{ "user_id": 1, "total_score": 1360, "correct_rate": 92.5, "play_duration": 185,
  "difficulty": "easy" }

// 成功
{ "ok": true, "record_id": 1 }

// 用户不存在
{ "ok": false, "msg": "用户不存在" }
```

约束：`total_score ≥ 0`、`0 ≤ correct_rate ≤ 100`、`play_duration ≥ 0`、
`difficulty ∈ {easy, normal, hard}`（非法值返回 422）。`play_time` 由数据库 `NOW()` 写入，前端不必传。

**两条分数 + 两个难度**：接口用 `INSERT ... ON DUPLICATE KEY UPDATE` 实现。同一用户再玩一局时：

- `total_score` / `difficulty` / 正确率 / 时长 / 时间 总是更新为本次这一局，对应排行榜「本次」列；
- `best_score = GREATEST(best_score, 本次得分)`，只升不降，对应「最高」列；
- `best_difficulty` 只在**破纪录时**跟着刷新，记录最高分是在哪个难度打出来的。

无论哪种情况都不会产生第二条记录，`record_id` 保持不变。
SQL 里 `best_difficulty` 的 `IF` 判断必须写在 `best_score` 更新之前，否则会读到已刷新的最高分。

**为什么要记难度**：初级 10 万分和高级 3 万分没有可比性。`/get_rank` 返回 `best_difficulty`，
前端据此把玩家分成「初级 / 中级 / 高级」三个区块，组内按 `best_score` 降序，避免跨难度误导。

### 4. GET /get_rank —— 排行榜（按最高分取前 30，前端分难度展示）

```json
{
  "ok": true,
  "rank": [
    { "rank": 1, "username": "testplayer", "total_score": 1360, "difficulty": "hard",
      "best_score": 2200, "best_difficulty": "normal",
      "correct_rate": 92.5, "play_duration": 185, "play_time": "2026-11-17 14:42:16" }
  ]
}
```

后端按 `best_score DESC` 返回前 30 条；前端按 `best_difficulty` 过滤成三组、每组取前 10 并重新编号。
`difficulty` 是最近一局难度（可能与 `best_difficulty` 不同），用于「本次」列的上下文。

排序：`total_score DESC, play_duration ASC`（同分时用时短的在前）。

### 5. GET /health —— 健康检查

```json
{ "ok": true, "db": "connected" }
```

数据库不可用时返回 `503`，是排查"前端连不上"最快的入口。

## 九、第五步：前端接入

`拼音战机.html` 顶部脚本中：

```js
const API_BASE = 'http://127.0.0.1:8000';   // 后端地址，部署到服务器后改这里
```

前端完整流程：

1. 启动 → 显示登录 / 注册页（也可点「游客模式直接试玩」跳过）。
2. 登录成功 → 进入开始页，显示 `欢迎，用户名`；点「排行榜」查看 Top10。
3. 选择难度开局 → 正常游戏。
4. 生命耗尽 → 结算页自动 `POST /save_game_record` 上报成绩，
   底部提示「成绩已上传 · 记录 #N」；游客模式提示「成绩未上传」。
5. 结算页点「排行榜」可直接查看自己刚刷新的名次。

**CORS**：后端已用 `CORSMiddleware` 放开 `allow_origins=["*"]`，
所以 `file://` 双击打开、`http://localhost`、`http://127.0.0.1` 都能直接调用。
上线后建议把 `*` 收敛为具体域名（见第十二节）。

## 十二、上线部署注意事项

1. **关闭 `--reload`**：生产环境不能开热重载，改为多进程：
   ```bash
   python -m uvicorn main:app --host 0.0.0.0 --port 8000 --workers 4
   ```
2. **CORS 收敛**：把 `allow_origins=["*"]` 改为实际域名，例如
   `["https://game.example.com"]`，并保持 `allow_credentials=False`
   （`*` 与 credentials 不能共存）。
3. **不要用 root 连库**：为应用单独建账号，只授予本库权限：
   ```sql
   CREATE USER 'pinyin_app'@'localhost' IDENTIFIED BY '强密码';
   GRANT SELECT, INSERT, UPDATE, DELETE ON pinyin_war_game.* TO 'pinyin_app'@'localhost';
   FLUSH PRIVILEGES;
   ```
4. **加反向代理**：Nginx 前置 443，转发到 `127.0.0.1:8000`，前端 `API_BASE` 改成
   `https://game.example.com`，同时避免浏览器对 `http` 混合内容的拦截。
5. **登录态**：当前 `user_id` 由前端保存，属于"轻量方案"，适合学习/小规模使用；
   若要防伪造，应改为 JWT 或 Session，并在 `/save_game_record` 校验 token 归属。
6. **备份**：定期 `mysqldump pinyin_war_game > backup.sql`，`.env` 单独保管。
